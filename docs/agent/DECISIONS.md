# Decisions

## 2026-05-17: Оставить Flutter и backend в одном репозитории

Status: accepted

Decision:

- Сохраняем текущий monorepo layout с `flutter_project/` и `backend_project/`.
- Ветки создаем под задачи, а не как долгоживущие ветки под отдельные модули.

Rationale:

- Flutter и backend сильно связаны API-контрактами.
- Auth, posts, events, chats, profiles и media URLs часто требуют связанных изменений.
- Один репозиторий позволяет ревьюить связанные изменения в одной ветке.

Consequences:

- Нужны четкие task names и labels, чтобы не смешивать несвязанные работы.
- Документация в `docs/agent/` помогает быстро продолжать работу в следующих сессиях.
- Делить на разные репозитории стоит только если deployment, ownership или release cycles реально станут независимыми.

## 2026-05-17: Использовать markdown task-файлы для долгой агентной работы

Status: accepted

Decision:

- Хранить постоянный контекст проекта в `docs/agent/`.
- На каждую существенную работу создавать отдельный task-файл.

Rationale:

- Проект достаточно большой, чтобы не полагаться только на контекст чата.
- Task-файлы упрощают паузу, продолжение, review и handoff.

Consequences:

- Каждое существенное изменение должно обновлять активный task-файл и `SESSION_LOG.md`.
- Долгосрочные решения нужно переносить из заметок в этот файл.
