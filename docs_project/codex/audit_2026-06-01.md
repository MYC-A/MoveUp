## Главные текущие риски

1. `PostItem` держит keep-alive для всей карточки.
   - Это сохраняет состояние, но может удерживать тяжелые карты и изображения в памяти.

2. Feed WebSocket debounce может терять промежуточные события.
   - `_handleWebSocketUpdate` отменяет предыдущий timer и обрабатывает только последнее событие из короткой пачки.
   - Для лайков/комментариев это может давать устаревшие счетчики.

3. В ленте не обрабатывается `comment_deleted`.
   - Backend broadcast отправляет `comment_deleted` с `comments_count`.
   - Flutter feed сейчас обновляет счетчик после удаления из bottom sheet через callback, но внешнее удаление по WebSocket может не обновить карточку.

4. Время постов парсится с ручным сдвигом `-5 hours`.
   - `Post.fromJson` вычитает 5 часов из `created_at`.
   - Backend отдает naive `isoformat()` без timezone, поэтому отображение времени зависит от окружения и может быть неверным.

5. Alembic scaffold есть без реальных миграций.
   - Пока неизвестно, как production DB будет переходить между версиями схемы.

6. Много `print/debugPrint` в backend/chat/posts/profile и Flutter UI/service слоях.
   - Не все опасны, но шум и потенциальные пользовательские данные надо чистить системно.

7. Docs/process mismatch.
   - В README была ссылка на `docs/agent`, но `.gitignore` игнорирует эту папку.
   - Текущая tracked память находится в `docs_project/codex`.

8. Тесты покрывают не все пользовательские сценарии.
   - Нет полноценных API/integration tests для заявок/уведомлений/чатов/ленты.
   - Flutter tests пока минимальные.

## Лента, посты, комментарии

Что уже сделано хорошо:

- `feed_screen.dart` стал тоньше: карточка поста вынесена в `widgets/feed/post_item.dart`.
- Карта маршрута в карточке вынесена в `_PostRouteMap`.
- Точки маршрута кешируются, preview прореживается до 150 точек.
- `VisibilityDetector` зумит карту один раз после появления.
- Карта обернута в `RepaintBoundary`.
- Tile layer вынесен в `widgets/common/osm_tile_layer.dart` и использует кеш тайлов.
- Комментарии уже работают через bottom sheet `widgets/post_comments_sheet.dart`.
- Backend broadcast для лайков, комментариев, удаления комментариев и удаления поста уже есть.

Что стоит поправить:

1. `PostItem` использует `AutomaticKeepAliveClientMixin` и `wantKeepAlive => true`.
   - Это может быть причиной роста памяти при длинной ленте с маршрутами.
   - Следующий шаг: сравнить scroll/memory с keep-alive только для нужных частей или без него.

2. `_handleWebSocketUpdate` в `feed_screen.dart` debounce-ит все события одним timer.
   - При быстрой пачке событий может примениться только последнее.
   - Лучше копить очередь событий или обновлять точечно без глобального debounce.

3. `comment_deleted` не применяется в feed handler.
   - Нужно обновлять `commentsCount` у поста и, если открыт comments sheet, синхронизировать локальный список.

4. Удаление комментариев в UI доступно только автору комментария.
   - Backend разрешает удалять комментарий автору комментария или владельцу поста.
   - Bottom sheet сейчас не знает владельца поста, поэтому владелец поста не видит действие удаления чужого комментария.

5. Удаление поста чистит записи в БД, но не видно удаления MinIO-объектов фотографий.
   - Возможны orphan-файлы в object storage.

6. `Post.fromJson` вручную вычитает 5 часов из `created_at`.
   - Лучше привести backend к timezone-aware UTC и на клиенте конвертировать через `toLocal()`.

## Чаты и push/WebSocket

Что уже сделано хорошо:

- WebSocket чата подключается с `?token=`.
- Backend проверяет JWT и сверяет `user_id` из path с `sub` токена.
- Flutter `ChatService` умеет reconnect с backoff.
- `ChatListScreen` дополнительно обновляет список/непрочитанные polling-ом.
- Push-сервис сделан optional и не должен ломать dev без Firebase env.

Что стоит поправить:

1. `active_connections: Dict[int, WebSocket]` хранит только одно соединение на пользователя.
   - Второй девайс/вкладка перезапишет первый socket.
   - Для нормального realtime нужно `Dict[int, set[WebSocket]]` или отдельная модель sessions.

2. Personal WebSocket payload для сообщения не содержит `created_at`.
   - `ChatScreen` показывает время из `created_at`; входящее realtime-сообщение может прийти без времени до перезагрузки.
   - Group message payload уже содержит `created_at`, personal message стоит выровнять.

3. `send_message` endpoint возвращает request schema, а не сохраненную запись.
   - Клиент сейчас игнорирует response, но для будущей синхронизации id/status/time лучше возвращать saved message DTO.

4. В chat backend много `print`.
   - Нужен нормальный logger и cleanup пользовательского/служебного шума.

5. Нет API/integration tests для chat WebSocket contract.
   - Минимально стоит покрыть auth mismatch, payload shape и multi-connection behavior.
